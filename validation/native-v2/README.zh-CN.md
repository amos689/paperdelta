# 原生文档试验 2：原文位置与明确绑定

[English](README.md)

PaperDelta 1.3.0 在查看留出文档文字与版式前冻结。110 个留出测量值中，冻结实现
**支持 82、漏检 3、错位 0、未知 25**；相同原文与标准位置上的已发行 1.2.1 为
支持 32、漏检 5、错位 0、未知 73。这是开发者标注、两个出版社的小规模试验，
不代表通用准确率、独立真人评审或对论文实验的复现。

## 选择与标注

[选择记录](selection.json)和[初始协议](protocol-initial.json)先于解析器修改。
十二个论文家族提供二十份原始许可文件：十二份文字 PDF、八份出版社 DOCX 附件。
PLOS 按 2024/2025 年各一月、七月四个日期分层，选取最早两篇元数据符合 DOCX 表格
条件的论文，第一篇用于开发，第二篇留出；eLife 最新四篇符合条件的正式研究版本
交替划分。正文和附件始终同组，每组十份文件。[来源清单](sources.json)记录作者、
许可、URL 与每份原文的哈希。

每份文件预设首张结果表的十二个测量数值及摘要/结果正文的四个数值，并规定缺项时的
补充顺序。排除标识符、日期、参考文献编号、图轴刻度和方法常量。查看后不替换文件。
五份附件没有合格结果，一份仅有一个，另有一份 PDF 仅有十三个，因此计划 320 个槽位
实际得到 **222 个目标**：开发 112、留出 110。98 个缺项在标准标注中明确保留，
既不算成功，也不虚构成未知目标。零目标文件仍保留在清单和转换器对照中。

标准位置来自独立 PDFium 字形坐标和原 OOXML 部件、段落与字符偏移，并结合原始
渲染图逐项检查。本机仅为视觉标注使用 Microsoft Word 只读导出 PDF；产品核验
不需要 Word。标注者是开发者。[开发标注锁](development-gold-lock.json)、
[实现锁](implementation-lock.json)、[留出标注锁](held-out-gold-lock.json)保留时序，
[首次运行开始记录](first-run-start.json)先于首次成绩。

PDFium 墨迹框不包含字形边距，而抽取跨度使用字体前进宽度。开发阶段、留出查看前，
[坐标修订](coordinate-amendment.json)增加同一原始字形的独立字体框。两个版本使用
相同的横向 1.2 点容差及纵向中心比较；原墨迹标注和初次墨迹模式成绩原样保留。
这是测量口径修正，不计作产品解析提升。

## 结果及剩余失败

| 输入 / 版本 | 支持 | 漏检 | 错位 | 未知 | 目标 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 开发 / 已发行 1.2.1 | 50 | 21 | 0 | 41 | 112 |
| 开发 / 冻结 1.3.0 | 76 | 0 | 0 | 36 | 112 |
| 留出 / 已发行 1.2.1 | 32 | 5 | 0 | 73 | 110 |
| 留出 / 首次冻结 1.3.0 | 82 | 3 | 0 | 25 | 110 |

“支持”要求独立标注的原始位置、唯一明确绑定、受控合成证据下通过，并在证据加一后
报出不一致。其他位置的同值不算成功。“漏检”表示没有唯一原始候选且没有针对该位置
的拒绝诊断；“错位”表示原文位置错误或绑定身份漂移；“未知”表示明确不支持结构或
身份无法确定，绝不计作成功。逐目标结果和依赖版本见[开发](results/development.json)、
[首次留出](results/held-out-first.json)及对应的
[开发基线](results/development-baseline.json)/[留出基线](results/held-out-baseline.json)。

首次运行的三个漏检保留如下：

- `held-034`、`held-040`：PLOS `0312751` 第 6 页密集结果表中的 29 和 18 未成为
  唯一原文候选。
- `held-086`：eLife `110200` 第 8 页完整科学计数值 `3 × 10⁴` 漏检。尾数、基数、
  指数是一个测量值，不能拆成三个容易的目标；任意上标指数版式仍不受支持。

未知包括 22 个原位置被拒绝、2 个锚点歧义及 1 个表格身份拒绝。native-v1 历史四个
PDF 漏检已通过[受控回归](results/historical-four-misses.json)，比较的是原字形的
独立字体框。native-v1 标准和成绩字节未变，这不属于新留出证据。

## 相同输入的 Docling 对照

Docling 2.134.0 在隔离环境运行，关闭 OCR、开启表格结构。默认后端在本 Windows
安装中无法打开六份开发 PDF；[记录](docling/development-default-runs.json)保留失败，
只隐去私有工作目录。其受支持的 PDFium 后端转换了全部二十份原文。
[环境与决策记录](docling/comparison.json)保存依赖版本、执行范围以及本版不将其加入
产品依赖的结论。

| 分组 | 在原容器中抽取 | 未在原位置抽取 | 原位置未知 |
| --- | ---: | ---: | ---: |
| 开发 | 96 | 0 | 16 |
| 留出 | 91 | 2 | 17 |

这些是**容器抽取计数，不是已接受的 PaperDelta 绑定**。PDF 数值必须出现在包含
独立原始框的唯一容器中，仅在别处找到同值不够。容器不能直接提供精确数值框或经复核
的实验身份。DOCX 输出缺少本试验要求的原 OOXML 段落/偏移，因此 33 个 Word 目标
的原位置均为未知。完整结构输出、逐项成绩及每文件用时保存在 [docling](docling/)。
较高的抽取数量本身不证明可用绑定更加可靠。

## 重放与许可

在匹配的源码目录中保留评测包后执行：

```sh
python -m pip install '.[dev]'
python tools/replay_native_v2.py --out build/native-v2-replay
```

使用新输出目录。重放检查归档实现哈希、运行两组并逐项比较历史结果，同时记录依赖
差异。再次运行属于已见文档回归，不能覆盖首次成绩或把修复结果称为新留出。
[冻结实现](implementation/)和[开发历史](development-history/)均保留。最初旧版基线
因 PDF 资源上限中断，不是完整成绩；完整基线将整份文档的拒绝明确记为未知。
