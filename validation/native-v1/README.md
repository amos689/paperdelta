# Licensed native Word/PDF study, v1

[简体中文](README.zh-CN.md)

This is a small, separately licensed native-document study for PaperDelta 1.1.
Four whole article families were split before native layout inspection: two for
development and two held out. Each family contains an unchanged publisher PDF and
original Word supplement. All four come from PLOS ONE; they do not represent the
diversity of scientific publishing. No independent human annotation is claimed.

## Protocol and outcomes

The [initial protocol](protocol-initial.json) fixes the split and 16 targets/file:
first 12 measured table tokens after headers, then four abstract/results/notes
tokens, falling back to later table values when measured prose is absent. Numeric
row IDs, method constants and dates are excluded. Gold records every fallback.
The [runtime amendment](annotation-runtime-amendment.json) was recorded before
implementation changes or held-out inspection: read-only Word 16 PDF export and
Poppler rendering replace unavailable LibreOffice; independent PDFium geometry
replaces unavailable pdftotext. Original hashes were checked before and after.

Development gold preceded parser work. The [implementation lock](implementation-lock.json)
froze all core files, package metadata and both extraction/scoring helpers before
held-out access. Held-out gold was selected from original OOXML/PDFium coordinates
and visually checked Word/PDF renders, then [locked](held-out-gold-lock.json) before
the [first scoring start](first-run-start.json). The original implementation is
preserved under `implementation/`; raw first-run results are never replaced.
An annotation setup failure and its correction are retained in
[setup-note.json](annotation/setup-note.json); no held-out score existed before that correction.

Results: [1.0 baseline](baseline/development-v1.0.json),
[1.1 development](results/development-v1.1.json), [first held-out](results/held-out-first.json).
The baseline checked matching controlled evidence; 1.1 additionally requires
changing every controlled value by +1 to produce a mismatch at the same original
position. It is not a like-for-like speed benchmark or reproduction of experiments.
Each 1.1 run retains configs, evidence, both reports and extraction diagnostics.
`results.csv` is the changed evidence; the baseline report retains the original values.

Supported means unique original position, explicit binding, pass against controlled
evidence and mismatch after its change. Unknown is an explicit unsupported/ambiguous
location, not success. Missed has no unique candidate or location-specific refusal.
Mislocated means a wrong token/position, even when numbers agree. Zero observed
mislocations is not a general guarantee. On held-out documents, Word had 0/32
supported targets; PDF had 4/32. Multi-number cells, irregular tables and uncertain
identities account for unknowns. Four PET PDF prose targets were missed because
extraction joined words and numbers. There is no blanket accuracy claim.

Owned rotation/crop/merge/note fixtures and eight bilingual browser flows are
separate regression checks, never counted as additional native articles or held-out
successes. See [1.1 release scope](../../docs/v1.1.md).

## Replay

Use a source checkout with this evaluation bundle unpacked at its root. Install
the versioned extras; exact original relevant dependencies are recorded in results:
python-docx 1.2.0, lxml 6.1.3, pdfplumber 0.11.10, pdfminer.six 20260107.

```sh
python -m pip install '.[dev,mcp]'
python tools/replay_native.py --out build/native-replay
python tools/evaluate_native.py --split all --out build/native-current-regression
```

Both commands require new output directories. The first copies frozen code and
study inputs into an isolated scratch checkout and compares every outcome with
the preserved runs. The second tests current code and records whether it matches
the original lock. Dependency versions are recorded separately. Repeated runs on
these now-seen documents are regressions, not new held-out evaluations.

The historical baseline harness is byte-preserved under `baseline/`. To rerun it,
use commit `169a3bee0c152ec6a2168426793489547b2bb5b8` and the original dependencies;
place the harness at `build/score_native_dev.py` and the protocol, development gold
and `papers/` at `build/native-v1/`. Keep historical and current outputs separate.
Annotation scripts retain their original scratch paths and are methodological
records; re-annotation must not overwrite the locked gold files.
