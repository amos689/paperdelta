# 2.0 Agent 映射研究

[English](README.md)

[评测协议](PLAN.zh-CN.md)在产品改动之前提交。
[tasks/manifest.json](tasks/manifest.json)包含 24 个自建任务：开发集和留出集各 12 个，
分别包含 8 个可映射案例、4 个必须拒答的案例。中英文请求各占一半，覆盖五种文稿格式。
这些是遵循仓库 MIT 许可的自建合成输入，并非独立标注的科研论文，也不是真人用户研究。

生成器为 [create_mapping_v5.py](../../tools/create_mapping_v5.py)。
首次生成因缺少可选的样本生成依赖 `openpyxl`，在 Excel 案例处停止。
安装 `openpyxl==3.1.5` 后，第二次生成完成。冻结前进一步补全了中文请求的翻译，
并加入运行环境和生成器的来源哈希。这些准备期间没有调用模型，也没有调优产品实现。
首次失败和中间输出保留在本地 build 目录，相关记录见
[preparation.json](preparation.json)。产品读取 Excel 不依赖 openpyxl。

实验身份、单位、归约方式和预期决策来自自建规格。Word/PDF 的原位置由既有 1.9 解析器
生成，并通过原文渲染进行了视觉核对，因此不构成独立的原生解析器金标准。
8 份原生文稿均已检查：数值和表格单元格清晰可读，文字无裁切，渲染没有改变原文件字节。
Poppler 渲染 Word 导出文件时报告缺少 Symbol 和 ArialUnicode 显示字体；
实际使用的 ASCII 测试文字显示正确。参见[视觉证据](visual/evidence.json)。

任务冻结时尚无模型推理成绩。留出集针对基于推理结果的调优隔离，并未对任务作者保密。
必须在产品与提示词冻结后才查看其首次模型结果，并保留全部首次输出。
参考答案和控制结果不得进入模型输入。

## 真实推理结果

五轮均调用本地 Qwen3-8B Q4_K_M 进行真实推理。完整映射要求声明的来源、实验身份、
记录选择、数量、单位、计算、显示及原始稿件位置全部满足冻结的严格契约。
生成有效建议或单纯匹配数字，都不能计为完整映射。

| 保留的运行 | 完整映射 | 必须拒答案例中的明确拒答 | 无效动作 / 全部动作 | 输入 / 输出 token | 实测推理秒数 |
| --- | --- | --- | --- | --- | --- |
| [旧任务回归 1](runs/regression-1/score.json) | 0/9 | 0/3 | 32/57 | 418,175 / 9,315 | 222.516 |
| [开发 1](runs/development-1/score.json) | 1/8 | 0/4 | 33/57 | 437,803 / 9,986 | 243.997 |
| [旧任务回归 2](runs/regression-2/score.json) | 0/9 | 0/3 | 20/55 | 389,243 / 8,219 | 197.860 |
| [开发 2](runs/development-2/score.json) | 0/8 | 1/4 | 21/50 | 384,348 / 7,626 | 194.845 |
| [首次留出运行](runs/held-out-1/score.json) | 1/8 | 2/4 | 25/48 | 362,571 / 7,140 | 180.922 |

选定的第二轮实现提供更明确的统计类型契约和通用阶段指导，但开发集完整映射从 1/8
下降至 0/8。[选择理由](selection-rationale.json)在[实现与提示词冻结](selection-freeze.json)
之前记录了这一取舍。查看留出结果后没有继续调优。这些结果不能证明映射准确率提高，
也不足以支持自主映射。这里的明确拒答只表示在必须拒答的案例上给出非空理由，
没有独立评估理由在语义上是否充分。预算耗尽不计作拒答。

首次留出运行中，仅 H02 完整映射；H06 生成错误建议；H04 不必要地拒答；
H11、H12 在必须拒答的案例上明确拒答；其余七例耗尽预算。
[原始运行目录](runs/)保留每次请求、响应、工具反馈、建议、失败、评分、初始提示词和
实现快照。[结果汇总](results-summary.json)记录五轮共 267 次动作、2,034,426 个 token、
1,040.140 秒实测推理。付费 API 费用为 0 美元，电费与硬件成本未测量。
部分运行期间同时执行了开发测试，因此这些时间是观测到的调用成本，不是隔离的速度基准。
整个研究没有接受任何绑定。

## 改动与固定条件

[开发记录](development-adjustments.json)保留最初机器失败和第一轮模型问题分析。
第二轮加入实际统计类型 schema，并明确来源、单位、数量与筛选指导。客户端以原始文本
提供作者备注，后续请求保留最新累积会话状态和上一次动作，移除过时的初始状态。
模型权重、采样参数、任务、参考答案、严格评分和每例 16 次动作、3 次无效动作、
每次最多 2,048 个输出 token 的预算均未改变。产品与客户端提示词同时变化，
本研究不能独立归因于其中某项。

[旧失败诊断](known-failure-diagnosis.json)保留原始 0/9 映射、0/3 拒答结果，
并区分旧评分器实际不依赖顺序的主键/种子比较与其归档文字描述。
新旧任务回归单独记录强制数量契约，不暗中替换或重算原始结果。
新任务要求完整数量契约和精确原生位置。

13 项自建参考/对抗控制检查确定性行为，模型调用次数为零。60 条已记录案例也通过
各自冻结实现重放。这两项都不是新的模型成功率、独立标注研究、真人精确率或确认耗时。
参见[发行验收](../../docs/zh-CN/v2.0.md)。

## 重放已记录的动作

在匹配的源码目录中安装开发依赖后，运行：

```sh
python tools/replay_mapping_v5.py --out build/mapping-v5-replay
```

使用新的输出目录。此命令不调用模型，也不需要模型权重。它核验[研究清单](study-index.json)，
把每份冻结实现复制到新的重放目录，执行已记录动作并核对反馈、建议和严格评分，
原始快照保持不变。旧协议锁没有把自身纳入自己的身份清单，导致回归快照复制器漏掉
这一元数据文件。[重放补充记录](replay-support.json)固定其与 `ca42e68` 相同的字节，
只向新的重放副本补充。首次重放失败和后续成功结果均保留在发行验收材料中。
研究清单排除了由解释器生成的字节码，未修改自建输入或已记录的推理源码/输出。

重新调用模型属于另一次实验。`python -m tools.evaluate_mapping_v5 --help` 说明
`prepare`、`run`、`score`、`freeze` 用法；须使用新的输出路径、明确启动的本机模型服务及
它的真实环境记录。[归档环境](runtime/run-3/model-provenance.json)包含模型 revision、
权重哈希、llama.cpp b11146 身份、启动命令和采样参数。本包不含模型或运行时二进制。
相同种子不保证不同硬件/运行时生成完全相同的输出。这些输入现在均已被观察，
今后在其上推理属于回归，不能称为新的留出研究。
