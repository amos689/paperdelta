# PaperDelta 0.4: Word manuscript review

[简体中文](zh-CN/v0.4.md)

The 0.4 line adds an optional Word reader to the existing evidence review workflow.
Install `paperdelta[docx]`, then run `paperdelta demo --document docx --out word-demo --open`.
The [Word guide](word.md) explains supported structures, native positions and limits.

Numbers split across Word runs are read together. Paragraph and table-cell positions
replace source line/byte addresses. Stable context and explicit table identities support
binding, batch selection and repair. The same checks, comparisons, snapshots, scope,
watch and read-only MCP tools work with DOCX. HTML includes the paragraph context and
English/Chinese position labels. Unsupported structures stay explicit and unverified.

Word manuscripts are never rewritten. The report gives suggested values and points to
the native paragraph or cell; make the edit in a document editor and rerun the check.
The core LaTeX install and guarded patch/recovery workflow retain their behavior.

## Upgrade

```sh
python -m pip install --upgrade 'paperdelta[docx]'
```

Configurations and reports using native documents require schema 3. Schema 1/2
LaTeX projects and historical reports remain readable. Regenerate unaccepted drafts,
proposals and patch files after a tool upgrade: their tool-version binding intentionally
prevents accepting stale work. Existing recovery transactions remain recoverable.

## Release checks

The maintained native suite has 22 positive Word fixtures and 110 labelled positions,
plus negative structure/package tests and end-to-end workflow tests. These complement
the existing LaTeX and historical compatibility suites; frozen evaluation evidence is
not rewritten. The test matrix covers Python 3.11–3.14 on Windows, Linux and both macOS
architectures. Package validation installs isolated core/full environments and audits
runtime bytes including the bundled DOCX example.

Release publication follows the [existing verified-artifact workflow](v0.3.md): build
once, pass checks for the release commit, publish a normal GitHub release and upload
those exact wheel/sdist bytes to PyPI with Trusted Publishing. The release's checksums
identify the published artifacts; past evidence remains associated with its own version.

Text PDF and multiple manuscript support belong to the next approved 0.5 line.
OCR, Word writeback and inferred scientific validity are outside this release.
