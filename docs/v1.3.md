# 1.3: More reliable native positions

[简体中文](zh-CN/v1.3.md)

This release improves Word/PDF review while keeping original documents read-only.
Every accepted result still needs declared evidence and a unique original position.
An extracted number is not evidence of a correct experiment identity.

## What changes

- Word tables retain explicitly omitted edge cells (`gridBefore`/`gridAfter`),
  including incomplete multilevel headers. Undeclared gaps and uncertain merges
  stay unverified.
- A cell such as `84.1 ± 1.2 (n = 3)` can contain independently selected values.
  Bindings retain the complete nonnumeric cell structure, header and row identity.
  Changing another result value or reordering labelled rows preserves identity;
  changing a label, adding a value or repeating indistinguishable contexts needs
  review. Selecting one component does not verify the statistical convention of
  the whole display; use the [statistical contract](statistics.md) for that.
- Studio's paper-location form accepts reviewed header-row counts and literal
  row labels. A reviewed numeric identifier such as `001` stays a string. The
  resulting anchor must resolve to the exact selected original position; choosing
  another row with the same result is rejected.
- PDF word spacing no longer joins common tight gaps into identifiers. Narrow
  column gutters remain separate. Unsafe words containing raised digits are
  isolated; unrelated visible words can still be checked if their identities are
  unique. A complex graphics page over the existing resource limit is reported
  as unverified without discarding other pages.
- Numeric-only contexts can exclude a longer intervening phrase when the same
  conjunction appears later in a paragraph. The original block identity and
  literal boundaries still have to match; repeated indistinguishable numbers
  remain ambiguous.
- Native diagnostics include original location hints and next actions. Use
  [PDF region previews](pdf.md#declare-regions) for named page regions; selecting
  a region never hides the rest of the paper from coverage.

## Isolated startup

With [uv installed](https://docs.astral.sh/uv/getting-started/installation/), the
same commands work in Windows PowerShell and macOS/Linux terminals:

```sh
uvx --python 3.12 paperdelta@1.3.0 demo --out paperdelta-demo --open
uvx --python 3.12 --from "paperdelta[docx,pdf]==1.3.0" paperdelta studio
```

Run Studio in the paper folder, or put `-C /path/to/paper` before `studio`.
`uvx` uses an isolated tool environment, as described in the
[uv tools guide](https://docs.astral.sh/uv/guides/tools/). The initial installation
can download dependencies and Python; installed checking remains local. A cached
environment can be reused offline. The `pdf` and `docx` extras are still optional;
missing ones produce an actionable dependency diagnostic. No Word/TeX installation
or model account is needed for checking.

## Share a diagnostic bundle

Studio → **Diagnostics** shows the complete contents before **Download diagnostic
ZIP** becomes available. Language switching retains the preview and form inputs.
The ZIP contains only `diagnostics.json`: tool/runtime/dependency versions, broad
OS/architecture, and diagnostic counts/codes. It excludes manuscript text,
evidence values, file names, personal paths, environment variables, error messages,
project identifiers and input hashes. Nothing is uploaded automatically.

The CLI offers the same review:

```sh
paperdelta diagnostics
paperdelta diagnostics --preview-id "sha256:REPLACE_WITH_REVIEWED_ID" --out diagnostics.zip
```

Use the actual `preview_id` returned by the first command. The export is refused
if the payload changed or the output already exists. Share the ZIP yourself only
after inspecting its contents. English/Chinese UI is selected with `--lang` or
the Studio language menu; fixed machine keys remain stable in both languages.

## Compatibility and validation

Configuration schema 9 introduces reviewed multi-value and numeric-only contexts.
Old configurations remain readable; newly used features trigger an explicit
schema upgrade in the normal proposal review. Existing anchors omit new default
fields to preserve their old identities. Stored report schema remains 8.

The PDF adapter identity changes to `paperdelta-pdf/3`. Existing PDF bindings
require explicit repair and rechecking; do not edit the parser string to bypass
review. Word/PDF writeback, OCR and arbitrary irregular table inference remain
outside the supported scope.

The [native-v2 study](../validation/native-v2/README.md) records the preselected
licensed originals, independent original positions, development/held-out split,
all four outcomes and the same-input Docling comparison. Historical v1 materials
retain their bytes. Authored unit/browser checks are separate from real-document
measurements and are not a human usability study.
