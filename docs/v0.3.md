# PaperDelta 0.3.0

[简体中文](zh-CN/v0.3.md)

This release focuses on faster setup and repeated review of an existing paper.
It uses a normal version number, with no alpha, beta or release-candidate stage.
The maintainer has received positive informal feedback from several users; there
is no new human-study gate and no claimed measured onboarding time or success rate.

## Delivered workflows

- `demo` creates a complete offline project and report from an installed core
  wheel, including original LaTeX/CSV inputs and pre-generated figure provenance.
- `batch guide` reuses CSV source/identity, unit, aggregation and expected-run
  choices across multiple metrics and explicitly selected paper locations.
- Contextual candidates and bounded literal table-cell anchors distinguish result
  columns; equal values alone are not identity evidence.
- `scope` previews numeric coverage restrictions and reasoned exclusions. Changed
  context makes exclusions stale; accepted failures cannot be hidden.
- `watch` coalesces saves, marks pending checks, performs complete rechecks and
  refreshes the bilingual report with an actionable review queue.
- Four in-memory batch MCP tools reduce repeated payloads and preserve explicit
  selection/confirmation. Seventeen project-read-only tools are available overall.
- All new UI messages and maintained workflows have English/Chinese versions.
  Both READMEs omit the Related work section.

The [workflow guide](workflows.md) contains commands, examples, limits and schema
migration. Configurations using new scope/table features become version 2 after
explicit acceptance; backups are retained. Existing version-1 configurations,
stored reports and snapshots remain readable. Tool-version-bound proposals and
patches should be regenerated, rather than forced through old hashes.

## Validation and evidence

The release uses the complete regression suite, static checks, bilingual document
and resource checks, real-browser report checks, clean core-wheel installs, archive
content audits and the sixteen-job [platform CI matrix](https://github.com/amos689/paperdelta/actions/workflows/ci.yml).
New cases cover a 20-cell batch, subset/cancel, wrong or missing experiment identity,
table changes, stale inputs, exclusions, continuous saves, data-only updates, MCP
session correction and byte-exact patch recovery. No machine run is labeled as a
human participant or as proof of a model's mapping accuracy.

The formal release and its attached checksums are on
[GitHub Releases](https://github.com/amos689/paperdelta/releases/tag/v0.3.0).
[Publication runs](https://github.com/amos689/paperdelta/actions/workflows/release.yml)
retain a separate receipt for the exact commit, CI run, distribution hashes and
isolated installation. Historical [v0.2 acceptance](v0.2-acceptance.md),
[Mac return](macos-validation-2026-10-03.md) and model failures retain their original scope.

## Publication procedure

The release process builds one wheel, one source distribution and a separate
evaluation ZIP. `SHA256SUMS` lists those three artifacts. Release `vX.Y.Z` must
match package metadata and a commit whose sixteen platform jobs all passed.
The `release.yml` workflow downloads those exact public assets, verifies their
hashes and contents, checks package metadata and installs the core wheel in a
clean environment. Only then can its isolated publication job send the wheel and
source distribution to PyPI. It does not rebuild a different package for PyPI.

PyPI uses [Trusted Publishing](https://docs.pypi.org/trusted-publishers/), with this
publisher configuration:

| Field | Value |
| --- | --- |
| PyPI project | `paperdelta` |
| GitHub owner | `amos689` |
| Repository | `paperdelta` |
| Workflow filename | `release.yml` |
| Environment | `pypi` |

For a first upload, use PyPI's pending-publisher form; for an existing owned project,
use its Publishing settings. Connecting GitHub as an account identity alone does
not establish this workflow-specific permission. No long-lived PyPI token belongs
in the repository. A published stable GitHub release triggers the workflow;
manual dispatch with the same tag can retry setup/network failures. Existing
uploads are not replaced. Verify the final PyPI file hashes against `SHA256SUMS`.

Git commits use the maintainer's GitHub noreply identity, without added coauthors.
Frozen evidence, archived implementations and original license notices are preserved.

## Subsequent work

Broader macro support, SD/SEM and interval statistics, experiment-platform
adapters, and a local graphical workspace remain future work. This release does
not claim arbitrary TeX support, automatic scientific validation or improved
model accuracy without an independent new measurement.
