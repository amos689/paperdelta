# PaperDelta 0.6: visual binding workbench

[简体中文](zh-CN/v0.6.md)

Run `paperdelta studio` inside a research project to connect evidence and paper
locations in a local browser. Source inspection, typed CSV/JSON metrics, derived
metrics, native positions, PDF page selection, previews and explicit subset
acceptance share the existing deterministic engine.

```sh
python -m pip install --upgrade 'paperdelta[docx,pdf]'
paperdelta -C path/to/project studio
```

See the [workbench guide](studio.md) for a complete walkthrough, draft downloads,
input changes, keyboard operation, limits and troubleshooting. Core-only LaTeX
users do not need optional parsers or Node.js. The interface and guide support
English and Chinese, including switching without losing explicit review selections.

## Compatibility

Configuration and report formats remain schemas 1–4. Existing LaTeX/Word/PDF
checks, snapshots, repairs, CLI and read-only MCP tools remain available.
This release adds an explicit browser confirmation path for numeric bindings;
MCP tools still do not accept mappings. Sources and metrics are saved only when
required by selected bindings. The old configuration is backed up.

Drafts/proposals from previous tool versions must be rebuilt. Current Studio
drafts can be downloaded and restored with the same tool version and unchanged
inputs. Session revisions reject edits from stale tabs; changed files invalidate
stages/previews. Browser values preserve Decimal and large integer identities.

Studio is a local, single-user tool on 127.0.0.1 with a random session token,
origin/host checks, strict request contracts and bounded requests. It serves fixed
assets without CDN or telemetry. Its form editing does not write papers, execute
research scripts, perform OCR or make scientific judgments.

## Acceptance evidence

Python tests cover the session workflow across all three formats, read-only
paper/data hashes, subset dependency closure, backups, stale inputs, explicit
preview requirements, undo/restore, exact decimals, path escapes and live HTTP
boundary/error behavior. Browser acceptance exercises six bilingual onboarding
flows, PDF highlights, draft roundtrips, language switching, report download and
desktop/mobile layout. Historical evaluation data and licenses retain their bytes.

The release workflow checks Windows/Linux and both macOS architectures on
Python 3.11–3.14, an additional browser job, isolated installed wheels and archive
content. Consult the release commit's Actions runs and validation bundle for the
actual passing results and artifact identities. Machine tests do not establish
usability or arbitrary-document extraction accuracy.
