# PaperDelta 0.8: batch binding in Studio

[简体中文](zh-CN/v0.8.md)

Studio now reuses explicit experiment definitions across result tables, saves
portable experiment templates, and imports existing CLI/MCP proposals into graphical
subset review. LaTeX, Word and text-PDF use the same evidence rules. Start with
`paperdelta studio`; the [Studio guide](studio.md) describes the complete workflow.

## Upgrade and compatibility

```sh
python -m pip install --upgrade 'paperdelta[docx,pdf]'
paperdelta -C path/to/project studio
```

Core-only LaTeX projects can install `paperdelta` without extras. Accepted
configurations, reports and snapshots keep their existing schemas. Compatible
0.6/0.7 drafts can be restored after validation; future/unknown draft versions are
refused. Imported proposals retain their exact original version and input guards.
Regenerate a proposal made by an earlier release before importing it.

## What changes

- Group CSV results by explicit experiment identity, filter the intended split,
  and reuse unit, reduction, record count, seed and display declarations.
- Browse 20 metrics or positions per page with search. Inspect typed evidence,
  context matches and missing identity fields before selecting positions. Equal
  values, including repeated table values, never select a mapping automatically.
- Reuse a saved template or download/import it into a compatible new source. A
  template contains a source contract and settings, never paper locations.
- Import numeric, claim and figure proposals produced by CLI or MCP. Review the
  exact definitions and accept a selected subset with its required dependencies.
  Imported drafts can be recovered and explicitly rebuilt after input changes.
- Keep all new controls and diagnostics available in English and Chinese,
  including language switching during cross-page selection.

Batch binding currently requires a declared CSV source. Use individual metric
binding for JSON or derived metrics. Different units and reductions need separate
batches. Missing or invalid evidence remains unknown and cannot be staged from the
batch catalog. Templates only fill the form; imports and staging do not accept
bindings. Manuscripts and evidence remain read-only. Existing local-only and
explicit acceptance controls apply unchanged.

## Measured setup effort

The same deterministic manuscript and CSV contain six model identities, four
result columns and three test seeds per model. All 24 means deliberately have the
same long-decimal value; `001` and `1` are distinct text IDs. The workflow declares
the source, maps all 24 cells and explicitly accepts every binding.

| Recorded browser interactions | Published 0.6.0 | 0.8.0 |
| --- | ---: | ---: |
| Clicks, text fills, selections and checks | 270 | 103 |
| Confirmed, passing bindings | 24 | 24 |

This is **61.9% fewer recorded interactions** on one machine-driven workflow,
not a measurement of human time, mistakes or arbitrary papers. Both paths retain
unchanged form values; the counter skips no-op fills, selections and checks.
Source setup and final individual acceptance are counted in both. Template and
language-switch validation are excluded from the comparison. Input SHA256 values
are identical. The baseline is the published 0.6.0 wheel, SHA256
`f1e33ad34d25cdaf294131e1fc755f70eea0c2e2afda142bf975799eb5b73eee`.
The complete [action traces](assets/v0.8/setup-effort.json) retain both paths.

## Reproduce verification

Install `.[dev,mcp]` and Playwright in a development environment, then run:

```sh
python tools/run_tests.py -q
node tools/validate_batch_browser.cjs build/batch-check --record
```

Always choose a new output directory. `PAPERDELTA_PYTHON`, `PLAYWRIGHT_MODULE` and
`BROWSER_EXECUTABLE` can identify local runtimes. The browser suite performs six
format/language flows, selects 24 positions across pages, reuses and imports a
template, accepts 12 bindings, imports a real CLI proposal for six more, then a
real read-only MCP proposal for the final six. It checks exact results, unchanged
manuscript/data hashes, PDF original-page highlights, mobile width, network requests
and browser errors. See the [browser receipt](assets/v0.8/browser-batch.json).

For the effort comparison, safely unpack the verified 0.6.0 wheel into a separate
directory and set `PAPERDELTA_BASELINE_RUNTIME` to that directory. Run the browser
command with a new output directory and `--effort-only`. It verifies the displayed
baseline version, input hashes, full acceptance and a reduction of at least 50%.
Normal CI does not download the historic baseline; it runs all current workflows.

`--record` captures actual English/Chinese browser screens. Encode them with
`python tools/encode_readme_demo.py build/batch-check/recording docs/assets/v0.8`.
The five-frame, 22-second playback is paced for reading and is not execution timing.
Existing onboarding, ongoing review and scale suites remain in CI alongside the
new batch suite. The release CI covers Windows/Linux and Apple Silicon/Intel macOS
with Python 3.11–3.14 and installed-wheel validation.

These fixtures validate interaction and identity handling, not the extraction
accuracy of unseen scientific documents. The separate real-document study remains
on the [approved roadmap](roadmap.md). Frozen evidence and licenses are unchanged.
