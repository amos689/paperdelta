# PaperDelta 1.7: review, revise and recover

[简体中文](zh-CN/v1.7.md)

1.7 joins manuscript context, declared experiment evidence and the next revision
action in Studio. Reviewed numeric patches now support literal `.tex`, `.md` and
`.qmd` source positions. Word and PDF remain read-only; annotated copies belong
to the subsequent 1.8 work, not this release.

## Work through a revision

```sh
paperdelta demo --document markdown --scenario safe-update --out revision-demo
paperdelta -C revision-demo studio
```

Use a new demo directory. In **Ongoing review → Review and revise**, search for
`table_accuracy`. Open the task to see the original context, written value,
expected display, exact metric definition and participating evidence. Search and
status filters page through all tasks; pagination does not drop selected edits.

Select **Include this numeric edit**, then **Preview selected edits**. Review the
diff before checking the confirmation and choosing **Apply reviewed changes**.
No location or write confirmation is selected automatically. The service rebuilds
the patch from the current accepted bindings and source bytes, rather than
trusting a browser-supplied replacement. A successful selected edit does not mean
the whole project passes: other numbers, claims, figures or exports may remain.

Changing language preserves the task search, status filter, selected numbers and
transaction choice, but clears write/recovery previews and confirmation. Changed
inputs or session revisions invalidate previews. Staged binding work must first
be accepted or explicitly cleared, so a source edit cannot discard that work.

False or unknown related claims block numeric patches. Recording that you looked
at a claim does not make it true or unblock it. Correct the evidence or manuscript
claim, review any changed binding, and check again. The default `changed` demo
deliberately shows this case; `safe-update` keeps the comparison true.

## Recover an edit

Open **Change history and recovery → Load change history**. Select a completed or
interrupted transaction, preview its diff, and explicitly confirm restoration.
The history remains available after restarting Studio. UTF-8 bytes, BOM and line
endings are preserved in the transaction backup. Later author edits cause a
conflict and are not overwritten. For multiple dependent transactions, start with
the latest applicable one.

The existing CLI exposes the same guarded operations:

```sh
paperdelta -C revision-demo check --report review/current
paperdelta -C revision-demo fix --report review/current/report.json --only table_accuracy --out selected.pdpatch.json
paperdelta -C revision-demo apply selected.pdpatch.json --dry-run
paperdelta -C revision-demo apply selected.pdpatch.json --write
paperdelta -C revision-demo recover TRANSACTION_ID
paperdelta -C revision-demo recover TRANSACTION_ID --write
```

Replace `TRANSACTION_ID` with the ID returned by `apply`. A mismatch from `check`
normally returns 1; incomplete evidence returns 2. These commands are separate
review steps, not a shell chain that assumes every check exits zero.

## Reuse a reviewed experiment

The **Define experiments** step starts with saved experiment definitions. Choose
the intended declared source, then an explicitly saved definition. **Load** lets
you inspect/edit the form. **Review candidates using this definition** reuses its
identity filters, units, aggregation, expected count/seeds, display and aliases
and opens joint review directly. No manuscript position is selected or accepted.

To create a reusable definition, fill the experiment form, open **Shared
experiment definitions**, preview its content and explicitly confirm saving.
Stored definitions are content-addressed. Incompatible source columns/types or
record keys are refused by the same backend validation as the existing CLI.
Editing a loaded form clears its accepted-definition reference.

## Boundaries and compatibility

- Checking, scanning, previews, ordinary Studio and MCP reads do not execute
  manuscript code. Explicit numeric writes use existing transaction guards.
- Source edits replace verified continuous numeric spans only. Unsupported
  Markdown/Quarto syntax, code, YAML and dynamic content remain unverified.
- Original Word/PDF documents are not modified. Their locations/evidence can be
  reviewed alongside source tasks, with explicit read-only reasons.
- Config schema 10, report schema 9, and patch/transaction schema 1 are retained.
  Older tools may reject the new source suffixes; use the current version for
  new patches. Patch tool versions must match; regenerate after upgrading.
- Compatible 1.6 Studio drafts are revalidated before migration. Existing LaTeX
  transaction backups remain recoverable; later manual edits still block recovery.

The authored browser validation covers five formats in both languages, selected
writes, language/input invalidation, restart recovery and narrow viewports.
The [installed browser record](assets/v1.7/revisions-installed.json) preserves
all ten workflows. [Comparison with published 1.6](assets/v1.7/comparison.json)
checks identical manuscript/data hashes. The selected LaTeX edit and recovery
previously required Studio plus CLI; both now complete in Studio. In the authored
24-position onboarding fixture, reviewed-definition reuse decreases from three
actions to one; the complete recorded flow decreases from 75 to 73 actions in
each language. This is not a claim of a similar improvement for arbitrary tasks.

[Actual 1.6 draft migration](assets/v1.7/draft-upgrade.json) and
[actual 1.6 transaction recovery](assets/v1.7/transaction-upgrade.json) preserve
their original inputs and restored bytes. Core regressions also cover forged patches, overlaps, Unicode/BOM/CRLF,
interrupted multi-file writes and false/unknown claim guards. These are developer
acceptance checks, not independent human usability or general extraction accuracy.
The [Windows installed-wheel run](assets/v1.7/installed-platform.json) passed
924 checks, with three POSIX-only checks skipped. The exact wheel also passed
13 isolated `uvx` starts. [Development adjustments](assets/v1.7/development-adjustments.json)
retain the earlier failures and their corrections. All 17 named jobs passed on the
[release commit](https://github.com/amos689/paperdelta/actions/runs/37565566327).
The [public-delivery record](assets/v1.7/publication.json) verifies GitHub and PyPI
artifact hashes and a fresh public installation across five formats in both languages.
