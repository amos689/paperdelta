# PaperDelta 0.7: review the next experiment in Studio

[简体中文](zh-CN/v0.7.md)

Studio now supports repeated review: snapshot comparison, grouped impacts,
maintenance of accepted declarations, position repair, claim review records,
continuous checking and durable draft recovery. The [Studio guide](studio.md)
explains every confirmation step and the remaining CLI operations.

## Upgrade

Install the new version in the environment that runs your project:

```sh
python -m pip install --upgrade 'paperdelta[docx,pdf]'
paperdelta -C path/to/project studio
```

Core-only LaTeX projects can install `paperdelta` without extras. No model key,
Node.js, TeX installation, cloud account or browser extension is required.

Accepted configurations, stored reports and snapshots keep schemas 1–4 and do not
need automatic rewriting. Existing CLI, read-only MCP and guarded LaTeX patch
workflows remain available. Word and PDF stay read-only. A browser declaration
edit writes only the accepted configuration and its backup, never the manuscript
or data. Existing snapshot names cannot be overwritten.

Downloaded, valid 0.6 drafts with unchanged inputs can be restored into 0.7.
Compatible earlier patch drafts retain the exact declarations and input hashes.
Future/unknown versions are refused. Accepted proposals still have their original
version/identity requirements; regenerate old previews before accepting them.

Successful staging actions save a bounded local recovery record. On restart,
restore or explicitly discard it before staging new work. If inputs changed,
select the declarations to retain, inspect a newly computed preview and confirm
staging; the original recovery record is archived. Conflicting names and invalid
old positions are refused. This does not accept the rebuilt bindings.

## What the browser checks

- Three formats × two languages: a second experiment after a named snapshot,
  false-claim review, declaration edits, native position repair, selected removal,
  restart recovery, changed-input rebuild and dependent group deletion.
- Language changes retain exact field values and selections while translating
  the surrounding controls and current report.
- Continuous checking exposes incomplete/partial saves and refuses stale
  previews. Recovery records cannot be silently overwritten by another server.
- Candidate search includes positions after 5,000 and preserves explicit choices
  across pages. Metric and impact cards show 20 items per page with search.

The maintained browser commands are:

```sh
node tools/validate_studio_browser.cjs build/studio-check
node tools/validate_review_browser.cjs build/review-check
node tools/validate_studio_scale.cjs build/scale-check
python tools/benchmark_studio.py --out build/studio-state --samples 20
```

Use new output directories. Install `.[dev]` and Playwright for development checks;
the installed product does not need those test tools. Runtime selectors and
instructions are in the [Studio guide](studio.md). The state benchmark separates
startup, first state and subsequent state timing; its scope excludes browser
rendering. The browser scale record includes actual local HTTP and DOM work.
Neither synthetic workload proves performance for arbitrary documents.

On the recorded Windows/Python 3.12 machine, the same 20-file, 500-metric,
10 MB CSV workload produced these results. The baseline uses the published 0.6.0
wheel (SHA256 `f1e33ad34d25cdaf294131e1fc755f70eea0c2e2afda142bf975799eb5b73eee`).
The input hashes are identical; each version has one first response and 20 later
responses, with the OS file cache warm.

| Measurement | 0.6.0 wheel | 0.7.0 |
| --- | ---: | ---: |
| Session initialization, excluding Python startup/imports | 2.960 s | 3.453 s |
| First state plus JSON serialization | 1.973 s | 1.995 s |
| Later state plus JSON serialization, P95 of 20 | 2.026 s | 0.222 s |
| State response bytes | 1,639,842 | 1,326,485 |

Caching improves repeated state requests; initialization and first-view cost are
not improved. The separate browser measurement reached the candidate after 5,000
in 309 ms including search debounce, and first displayed the 500-metric project
in 2.672 s after navigation, following 3.648 s of server startup. These are single
browser samples. Raw [baseline](assets/v0.7/state-v0.6.json),
[current state](assets/v0.7/state-current.json), [browser scale](assets/v0.7/browser-scale.json),
[onboarding](assets/v0.7/browser-onboarding.json) and
[ongoing review](assets/v0.7/browser-review.json) records are retained.

The README's five real-screen frames are recorded with the review command's
optional `--record` flag and encoded with
`python tools/encode_readme_demo.py build/review-check/recording docs/assets/v0.7`.
The 22-second playback is paced for reading, not an execution-time measurement.

The release commit's [CI runs](https://github.com/amos689/paperdelta/actions/workflows/ci.yml)
provide Windows/Linux and both macOS architectures on Python 3.11–3.14, installed
wheel checks and the browser evidence bundle. The new flows extend machine
acceptance, not human usability or native-document extraction accuracy. Original
study records and licenses remain byte-for-byte unchanged.
