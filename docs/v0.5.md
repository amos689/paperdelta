# PaperDelta 0.5: PDF and source/export review

[简体中文](zh-CN/v0.5.md)

The 0.5 line adds optional text-PDF checking, original-page highlights and multiple
manuscripts sharing explicit metrics. A declared `export_of` relation identifies
a source that has been corrected while its exported PDF remains stale. Word
support from 0.4 and the existing LaTeX workflow remain available.

```sh
python -m pip install --upgrade 'paperdelta[docx,pdf,mcp]'
paperdelta demo --document pdf --out pdf-demo --open
```

Install only the extras you need. The core package still works offline on LaTeX
without a PDF/Word parser. See the [PDF and multiple-manuscript guide](pdf.md) for
commands, native coordinate semantics, region declarations and supported layouts.
All added CLI/report interfaces and maintained guides support English and Chinese.

## Compatibility and limits

Configuration/report schema 4 carries PDF positions, extraction identities,
companions and export comparisons. Readers retain schema 1–3 support. The version
of an existing LaTeX/Word configuration changes only when a new feature is
accepted. Configuration changes have previews, input checks and backups.
Unaccepted drafts, proposals and numeric patches must be regenerated after a tool
upgrade. Historical recovery transactions remain recoverable.

PDF parser changes require explicit binding repair. Unsupported/scanned regions
remain unknown. Word and PDF are read-only; suggestions point back to the document
editor or source export workflow. OCR, general layout reconstruction, native
writeback, Excel and statistical inference are not part of this release.

The native numeric-span validator also now rejects a selection that stops inside
a longer number. Original-page previews use only bytes matching the checked
input hash and carry bounded page/image/highlight limits. Preview availability
does not change consistency verdicts.

## Reproducible acceptance

The maintained native suites contain **22 Word structures / 110 labelled
positions** and **25 PDF layouts / 125 labelled positions**. PDF tests compare
page and horizontal coordinates to independently authored drawing positions,
and vertical boxes to the known source baseline. They include Chinese, split
drawing calls, signed/scientific numbers, columns, ruled tables and page sizes.
Additional cases cover ambiguity, partial numbers, hidden/translucent text,
scans, forms, merged cells, region boundaries, parser changes, stale proposals,
repairs, batch binding, watch, read-only MCP and source/export disagreements.
These original fixtures do not constitute an accuracy estimate on arbitrary PDFs.

Release acceptance also runs historical compatibility and the full suite on
Python 3.11–3.14, Windows/Linux and both macOS architectures; isolated core/full
installs; package audits; EN/CN desktop/mobile offline-browser checks; and
separate cold-process, warm-process, HTML-only and original-page-render timings.
Warm checks still reread and reparse files. No cross-machine timing guarantee is
inferred from local measurements.

Inspect the release commit's successful Actions jobs and attached validation
bundle for actual commands, test totals, platform results, timings and identities.
The normal GitHub release and PyPI use the same verified wheel/sdist bytes.
`SHA256SUMS` and `VALIDATION_SHA256SUMS` bind the released files and validation
bundle. Historical evidence under `docs/evidence`, `tests/corpus` and `evaluations`
retains its original bytes and version association.
