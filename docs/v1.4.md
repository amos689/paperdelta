# PaperDelta 1.4: fewer setup steps, explicit experiment review

[简体中文](zh-CN/v1.4.md)

Version 1.4 organizes initial binding into **paper and data → define experiments →
review and confirm**. Original manuscripts remain read-only. Accepted configurations
keep the existing schema; new optional batch fields preserve old batch identities
when absent. Individual metric and location editors remain available.

## Review a source contract

Open Studio, inspect a data source and choose **Suggest types and primary keys**.
Each proposed type and key has a reason. Leading-zero identifiers stay strings;
an Excel cell's stored numeric/text kind matters. Only a complete table of at most
10,000 rows can yield a uniqueness claim. Duplicate identities, missing values,
mixed Excel storage and incomplete samples remain visible. A measurement column
is never chosen as an identity solely because its current values are unique.

Choose a proposed key and explicitly apply it, then stage the source. Suggestions
do not change accepted declarations. In stage two, **Suggest experiment groups**
offers fields, grouping columns, constants and repeat columns. Review the choices;
units, reductions, record counts and seeds still need an explicit contract.

## Review evidence beside original positions

Generate the batch and enable **Review evidence and original positions together**.
Each card shows a metric's identity, unit, reduction, count, seed guard and contributing
evidence beside original context. Up to three equally strong context candidates
are shown, with their total and a way to inspect every original position. Context
ranking never uses numeric equality. Missing identities stay visible. Nothing is
preselected, and a location cannot be assigned to two different metrics in one batch.

Select each position, explain the mapping, stage, then preview. **Select all displayed
bindings I have reviewed** is an explicit final-selection control; individual
checkboxes and subset acceptance remain available. The final attestation and
acceptance are still separate. Language switching preserves inputs and selections.

The same unchanged 24-metric fixture took 54 non-no-op browser operations in the
first v1.4 run, including two language switches, versus the preserved v0.8 count
of 103 and v0.6 count of 270. Six format/language flows passed. This measures authored
browser actions, not human completion time or independent usability. See the
[recorded measurement](assets/v1.4/onboarding.json).

## Shared definitions and reviewed labels

An experiment definition includes the source contract, grouping/filter selectors,
fields, units, reductions, seeds, display and explicit identity labels. For example,
you may declare that paper label `Ours` refers to source model `001`, with the
experimental evidence for that declaration. The same column/label cannot refer
to both `001` and `1`. Result fields cannot supply identity labels.

Use **Shared experiment definitions** to preview the complete definition and
confirm it. The content-addressed file is saved under `.paperdelta/experiments/`.
Load it into another batch with a compatible source contract. Changing settings
detaches the reference until a new reviewed definition is saved; it never changes
previously accepted bindings. Labels explain context suggestions, while original
literal anchors and explicit location choice remain necessary.

Accepted metrics retain resolved contracts. The definition fingerprint is retained
in the binding rationale and local `.paperdelta/binding-reviews/` record, together
with selected bindings, evidence hashes and before/after configuration hashes.
A record captures a reviewed selection; its presence alone does not prove the
configuration write completed. Compare `config_after_sha256` with the configuration
bytes when auditing application. Records and source data are never uploaded.

## A bounded Agent proposal workflow

Install the optional MCP extra and use `paperdelta mcp`. The new read-only tools are:

1. `inspect_source_contract`: inspect type/key/group suggestions and their limits.
2. `inspect_experiment_definitions`: inspect saved, reviewed shared definitions.
3. `start_mapping_session`: receive discovery, typed stage schemas and allowed actions.
4. `advance_mapping_session`: supply the current revision, action and flat arguments.
5. `inspect_mapping_session`: inspect or export the last valid draft.

Stages are `source`, `metric`, `derived`, `locations`, then `finish`; `abstain` ends
the session with a reason. Sessions allow 16 actions and at most three invalid
actions, expire after an hour and remain process-local. Errors retain the last
valid draft and expose field paths, the diagnostic and a correction hint. Inputs
changing terminate the session as stale. Identifiers are distinct from file paths;
source units are distinct from paper display conventions.

`finish` performs deterministic proposal checking and returns an unaccepted
proposal plus its check summary. Import it into Studio or use normal CLI inspection
and acceptance. MCP never accepts bindings, saves experiment definitions or writes
papers. Existing stateless and batch MCP tools remain available; batch requests
can reference saved definitions and explicit identity labels.

The [real-model study](../validation/mapping-v4/README.md) preserves the initial
failure and a separately frozen corrective revision. A syntactically valid proposal
does not establish the correct experimental identity. No autonomous mapping claim
is made, and deterministic regression checks are reported separately from model results.

## Compatibility and checks

Compatible saved drafts from 0.6–1.3 can be reviewed and restored; changed parser
identities or inputs still require normal repair/rebuild. Config schema remains 9,
stored report schema remains 8. Word/PDF optional extras, offline operation and
English/Chinese switching are unchanged.

The installed package, bilingual browser flows, exact public artifacts and all
17 named Windows/Linux/macOS/Python CI jobs must pass before stable publication.
The [delivery ledger](roadmap.md) records publication only after verification.

Local Windows verification passed 801 tests with three POSIX-only skips, six
installed-wheel onboarding flows, two shared-definition flows and thirteen isolated
startup checks. An actual published 1.3 installation produced a draft that 1.4
restored without changing its bindings or input/configuration bytes.
