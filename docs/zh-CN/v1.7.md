# PaperDelta 1.7：审查、修订与恢复

[English](../v1.7.md)

1.7 在 Studio 中汇总原文上下文、已声明的实验证据及下一步修订动作。
经明确复核的数值补丁现支持 `.tex`、`.md` 和 `.qmd` 字面源码位置。
Word/PDF 仍保持只读；批注副本属于后续 1.8 工作，不计入本版能力。

## 完成一项修订

```sh
paperdelta --lang zh-CN demo --document markdown --scenario safe-update --out revision-demo
paperdelta --lang zh-CN -C revision-demo studio
```

每次使用新的演示目录。在“日常审查 → 审查与修订”中搜索 `table_accuracy`。
打开任务，即可查看原文上下文、论文中的值、预期显示、精确的指标定义及参与计算
的证据。搜索和状态筛选覆盖全部任务，翻页不会丢失所选修改。

勾选“加入这处数值修改”，点击“预览所选修改”。复核差异后，再勾选确认并点击
“应用已复核的修改”。位置和写入确认均不默认勾选。服务端会根据当前已接受绑定
与源码字节重新生成补丁，不信任浏览器传来的替换内容。所选修改成功不代表整个
项目通过；其他数字、结论、图形或导出稿可能仍有任务。

切换语言保留任务搜索、状态筛选、所选数字及事务选择，但清除写入/恢复预览和确认。
输入或会话版本变化会使旧预览失效。尚有暂存绑定时，应先接受或明确清除，避免修改
源文件时丢弃这些工作。

错误或未知的相关结论会阻止数值补丁。记录“已经看过这条结论”不会使其变为真实，
也不会解除阻止。请修正证据或论文结论，复核变化后的绑定，再重新检查。默认
`changed` 演示有意展示此情况；`safe-update` 保持比较结论成立。

## 恢复修改

打开“修改历史与恢复 → 读取修改历史”，选择已完成或中断的事务，预览恢复差异，
再明确确认。Studio 重启后仍可读取历史。事务备份保留 UTF-8、BOM 和换行符的原始
字节。作者后续编辑会触发冲突，不会被覆盖。存在多次相互依赖的修改时，应从最新
且适用的事务开始恢复。

原有 CLI 使用相同的受保护流程：

```sh
paperdelta --lang zh-CN -C revision-demo check --report review/current
paperdelta --lang zh-CN -C revision-demo fix --report review/current/report.json --only table_accuracy --out selected.pdpatch.json
paperdelta --lang zh-CN -C revision-demo apply selected.pdpatch.json --dry-run
paperdelta --lang zh-CN -C revision-demo apply selected.pdpatch.json --write
paperdelta --lang zh-CN -C revision-demo recover TRANSACTION_ID
paperdelta --lang zh-CN -C revision-demo recover TRANSACTION_ID --write
```

将 `TRANSACTION_ID` 替换为 `apply` 返回的事务 ID。`check` 发现不一致通常退出 1，
证据不完整退出 2。上述命令是分开的复核步骤，不是要求每一步退出零的命令链。

## 复用已复核实验

“定义实验”步骤首先展示已保存的实验定义。选择要使用的已声明数据源，再选择
已明确保存的定义。“载入”用于查看或编辑表单；“按此定义审查候选位置”复用
身份筛选、单位、聚合、预期数量/种子、显示和别名，直接进入联合复核。
不会自动选中或接受论文位置。

首次保存时，填写实验表单，展开“共用实验定义”，预览内容并明确确认保存。
定义以内容身份保存。不兼容的数据源列、类型或记录主键会被与 CLI 共用的后端
校验拒绝。修改已载入表单会清除其已接受定义引用。

## 边界与兼容性

- 检查、扫描、预览、普通 Studio 和 MCP 读取不执行论文代码；明确的数值写入
  使用原有事务保护。
- 源码修改仅替换经过验证的连续数值区间。不支持的 Markdown/Quarto 语法、代码、
  YAML 和动态内容继续保持未验证。
- 不修改 Word/PDF 原文。可以在任务旁查看其位置与证据，并看到明确的只读原因。
- 保留配置 schema 10、报告 schema 9 及补丁/事务 schema 1。旧工具可能拒绝新的
  源码后缀，新补丁请使用当前版本。补丁工具版本必须一致，升级后应重新生成。
- 兼容的 1.6 Studio 草稿在迁移前重新验证；既有 LaTeX 事务备份仍可恢复，后续
  手工编辑仍会阻止恢复。
