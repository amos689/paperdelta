# 1.3：更可靠的原生文档定位

[English](../v1.3.md)

本版改进 Word/PDF 审查，原始文档仍保持只读。每个已接受结果都需要明确的证据声明
和唯一原文位置；读到了数字，不代表找对了实验身份。

## 改进内容

- Word 表格保留明确声明的边缘空缺单元格（`gridBefore`/`gridAfter`），包括部分
  不完整多层表头。未声明空洞和无法确定的合并继续保持未验证。
- `84.1 ± 1.2 (n = 3)` 这样的单元格可以分别选择多个值。绑定保留完整非数字结构、
  表头和行身份。邻近结果数值变化或带标签行重新排序后，身份可以保留；改变文字、
  增加数值或出现无法区分的重复上下文需要复核。单独绑定一个分量不等于验证整个
  统计表达的约定；完整校验请使用[统计契约](statistics.md)。
- Studio 论文位置表单支持填写已复核的表头行数及原文行标签。`001` 这样的数字标识
  仍是字符串。生成的锚点必须回到所选原文位置；另一个相同数值的行不能代替它。
- PDF 改善了紧密单词间距和数字粘连问题，较窄分栏间隙仍分开处理。含上标数字的
  不可靠词片段被隔离，同一行其他可见片段在身份唯一时仍可核验。图形页超过已有
  资源限制时明确记为未验证，其他页面仍继续检查。
- 纯数值上下文可以排除重复连接词之间夹入的长短语，但原始文本块身份和前后原文
  仍必须匹配；无法区分的重复数值继续保持歧义。
- 原生诊断增加原文位置提示及下一步操作。命名页面区域请使用
  [PDF 区域预览](pdf.md#声明区域)；选定区域不会隐藏论文其余部分的覆盖缺口。

## 隔离启动

先[安装 uv](https://docs.astral.sh/uv/getting-started/installation/)，以下命令可用于
Windows PowerShell 和 macOS/Linux 终端：

```sh
uvx --python 3.12 paperdelta@1.3.0 --lang zh-CN demo --out paperdelta-demo --open
uvx --python 3.12 --from "paperdelta[docx,pdf]==1.3.0" paperdelta --lang zh-CN studio
```

在论文目录运行 Studio，或在 `studio` 前加入 `-C /path/to/paper`。
`uvx` 使用隔离的工具环境，详见 [uv 工具指南](https://docs.astral.sh/uv/guides/tools/)。
首次安装可能下载依赖和 Python，安装后的核验在本地进行，已有缓存环境可离线复用。
`pdf` 和 `docx` 扩展仍按需安装，缺失时会提示安装方法。检查不需要 Word、TeX 或模型账号。

## 分享诊断包

Studio → **诊断信息**先显示完整内容，复核后才能下载 ZIP。切换语言保留预览和表单输入。
包中只有 `diagnostics.json`：工具、运行时、依赖版本，概括的系统/架构，以及诊断计数和代码。
不包含论文文字、证据值、文件名、个人路径、环境变量、报错原文、项目标识或输入哈希，
也不会自动上传。

CLI 使用同样的预览流程：

```sh
paperdelta --lang zh-CN diagnostics
paperdelta --lang zh-CN diagnostics --preview-id "sha256:替换为已复核的ID" --out diagnostics.zip
```

请使用第一条命令实际返回的 `preview_id`。内容变化或输出已存在时拒绝导出。
检查内容后再自行分享 ZIP。`--lang` 或 Studio 语言菜单切换中英文；机器字段名在两种语言中
保持稳定。

## 兼容与验证

配置版本 9 引入已复核多值单元格和纯数值上下文。旧配置仍可读取，使用新能力时通过正常
提案审核明确升级。旧锚点省略新增默认字段以保留原身份；存储报告仍为版本 8。

PDF 适配器身份变为 `paperdelta-pdf/3`。已有 PDF 绑定需要明确修复并重新检查，不应直接
修改解析器字符串绕过复核。Word/PDF 写回、OCR 和任意不规则表格推断仍不在支持范围内。

[native-v2 试验](../../validation/native-v2/README.zh-CN.md)记录预先选定的授权原件、独立原文
位置、开发/留出拆分、全部四类结果，以及相同输入下的 Docling 对比。历史 v1 材料保留原字节。
人工编写的单元/浏览器回归与真实文档测量分开记录，不将它们称作真人可用性研究。
