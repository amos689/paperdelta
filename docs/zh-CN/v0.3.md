# PaperDelta 0.3.0

[English](../v0.3.md)

本版聚焦更快接入和持续审查已有论文，采用正常发行版本号，不设置 Alpha、Beta
或 RC 阶段。维护者已收到数位用户的正面试用反馈，不另设真人试验门槛，也不据此
声称测得了接入耗时或成功率。

## 交付工作流

- `demo` 从纯核心 wheel 创建完整离线项目与报告，包含原创 LaTeX/CSV 和预生成图来源。
- `batch guide` 在多个指标及明确选择的论文位置间复用 CSV 来源、身份、单位、聚合
  和预期实验运行选择。
- 依据上下文提出候选，以限定的字面表格单元格锚点区分结果列，不凭数字相同判断身份。
- `scope` 预览数字覆盖范围及有理由的排除；上下文变化使排除过期，不能隐藏已接受的失败。
- `watch` 合并连续保存、标记等待重查、完整复检，并刷新带处理清单的双语报告。
- 四个内存批量 MCP 工具减少重复传递，保留明确选择与确认。共提供十七个项目只读工具。
- 所有新增界面提示和维护工作流同步中英文，两个 README 均移除 Related work。

[工作流指南](workflows.md)提供命令、例子、限制及 schema 迁移说明。明确接受新的
范围或表格特性后，配置升级为版本 2 并保存备份；已有版本 1 配置、存储报告和
快照仍可读取。限定旧工具版本的提案及补丁应重新生成，不绕过旧哈希校验。

## 验证与证据

发行采用完整回归、静态检查、双语文档和资源检查、真实浏览器报告验证、纯核心
安装、归档内容审计及十六项[平台 CI](https://github.com/amos689/paperdelta/actions/workflows/ci.yml)。

正式发行和文件校验值见 [GitHub Releases](https://github.com/amos689/paperdelta/releases/tag/v0.3.0)。

## 发布流程

构建一份 wheel、一份源码包和独立评测 ZIP，`SHA256SUMS` 列出三个文件的哈希。
`vX.Y.Z` 标签必须与包元数据一致，对应提交的十六项平台检查必须全部通过。
`release.yml` 下载该发行页的原始产物，核对哈希和内容、检查元数据，并在新环境
安装纯核心 wheel。之后独立发布任务才将 wheel 和源码包发送到 PyPI，不另行重建。

PyPI 采用 [Trusted Publishing](https://docs.pypi.org/trusted-publishers/)，配置如下：

| 字段 | 值 |
| --- | --- |
| PyPI 项目 | `paperdelta` |
| GitHub 所有者 | `amos689` |
| 仓库 | `paperdelta` |
| 工作流文件名 | `release.yml` |
| 环境 | `pypi` |

首次上传使用 PyPI 的 pending publisher 表单；已有自有项目使用 Publishing 设置。
仅将 GitHub 关联为账号身份，不等于授予这份工作流发布权限。仓库不保存长期 PyPI
令牌。发布正常 GitHub Release 后触发流程；遇到配置或网络失败时可用相同标签
手动再次运行。已有上传不覆盖，最终核对 PyPI 文件与 `SHA256SUMS` 一致。

Git 提交继续使用维护者的 GitHub noreply 身份，不增加共同作者。冻结证据、归档实现
和原始许可声明保持不变。
