# PaperDelta 0.7：在 Studio 中审查下一轮实验

[English](../v0.7.md)

Studio 现在支持反复使用的审查流程：快照比较、影响分组、已有声明维护、位置修复、
结论复核记录、持续检查及持久草稿恢复。[工作台指南](studio.md)说明每一步确认，
以及仍通过 CLI 完成的操作。

## 升级

在运行项目的环境中安装新版本：

```sh
python -m pip install --upgrade 'paperdelta[docx,pdf]'
paperdelta --lang zh-CN -C path/to/project studio
```

仅处理 LaTeX 时可安装不带 extras 的 `paperdelta`。无需模型密钥、Node.js、TeX、
云账号或浏览器扩展。

已确认配置、已保存报告和快照保留 schema 1–4，无需自动改写。已有 CLI、只读 MCP
及受保护的 LaTeX 补丁工作流继续可用。Word/PDF 保持只读。浏览器声明编辑只写入
已确认配置及其备份，不写稿件或数据；已有快照名称不能覆盖。

合法的 0.6 下载草稿，在输入未变时可以恢复到 0.7。兼容的较早补丁版本草稿保留
准确声明和输入哈希，未知或未来版本会被拒绝。接受提案仍遵循原有的版本与身份
要求，旧预览应重新生成后再确认。

每次成功暂存保存有大小上限的本地恢复记录。重启后，先恢复或明确丢弃，再暂存
新工作。输入变化时，可以选择需保留的声明、检查重新计算的预览并确认暂存；
原恢复记录会归档。冲突名称和失效旧位置会被拒绝，这一步不会接受重建后的绑定。

## 浏览器验证范围

- 三种格式 × 两种语言：命名快照后的第二轮实验、失败结论复核、声明编辑、原生
  位置修复、明确删除、重启恢复、输入变化后重建，以及依赖声明的整组删除。
- 语言切换保留字段原值与选择，同时翻译操作说明及当前报告。
- 持续检查保留不完整或部分保存状态，拒绝过期预览；不同服务不能静默覆盖恢复记录。
- 候选搜索覆盖第 5,000 项之后的位置，跨页选择保持明确；指标和影响卡片每页
  20 项，支持搜索。

维护的验收命令为：

```sh
node tools/validate_studio_browser.cjs build/studio-check
node tools/validate_review_browser.cjs build/review-check
node tools/validate_studio_scale.cjs build/scale-check
python tools/benchmark_studio.py --out build/studio-state --samples 20
```

每次使用新输出目录。开发检查需要安装 `.[dev]` 和 Playwright，用户安装成品时
不需要这些测试工具。运行时选择及说明见[工作台指南](studio.md)。状态测量分别记录
启动、首次状态与后续状态耗时，不含浏览器渲染；浏览器规模记录包含实际本机 HTTP
和 DOM 操作。这些合成负载不能证明任意文档的性能。

记录所用的 Windows/Python 3.12 机器上，对相同的 20 文件、500 指标、10 MB CSV
负载，测得下表。基线使用已发布的 0.6.0 wheel，SHA256 为
`f1e33ad34d25cdaf294131e1fc755f70eea0c2e2afda142bf975799eb5b73eee`。
两版输入哈希一致，每版记录首次响应和后续 20 次响应，未清空系统文件缓存。

| 测量项 | 0.6.0 wheel | 0.7.0 |
| --- | ---: | ---: |
| 会话初始化，不含 Python 启动与导入 | 2.960 秒 | 3.453 秒 |
| 首次状态及 JSON 序列化 | 1.973 秒 | 1.995 秒 |
| 后续状态及 JSON 序列化，20 次 P95 | 2.026 秒 | 0.222 秒 |
| 状态响应字节数 | 1,639,842 | 1,326,485 |

缓存改善了重复请求；初始化与首次显示成本没有改善。独立浏览器测量中，搜索第
5,000 项之后的候选耗时 309 毫秒，包含搜索防抖等待；500 指标项目的服务启动为
3.648 秒，随后页面导航至首次显示为 2.672 秒。这些都是单次浏览器样本。保留原始
[基线](../assets/v0.7/state-v0.6.json)、[当前状态](../assets/v0.7/state-current.json)、
[浏览器规模](../assets/v0.7/browser-scale.json)、[首次接入](../assets/v0.7/browser-onboarding.json)
和[日常审查](../assets/v0.7/browser-review.json)记录。

README 的五帧真实界面通过日常审查命令的可选 `--record` 参数录制，再运行
`python tools/encode_readme_demo.py build/review-check/recording docs/assets/v0.7`
编码。22 秒播放时间经过阅读节奏编排，不是执行耗时测量。
