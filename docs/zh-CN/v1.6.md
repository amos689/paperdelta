# PaperDelta 1.6：从实验输出到修订清单

[English](../v1.6.md)

1.6 增加可审核的 Notebook／Quarto 生成记录、LaTeX／Markdown 结果片段，
以及连通数值陈述、结论、图形和导出稿的修订清单。保留明确的证据身份与已有
五种论文格式。Notebook 支持检查保存的单元格和声明文件，不把任意输出直接当作已确认证据。

## 查看保存的 Notebook

```sh
paperdelta --lang zh-CN provenance notebook analysis.ipynb
```

检查在本地只读进行，显示稳定的单元格 ID、代码／输出哈希、保存的执行次数和错误。
nbformat 4.5+ 要求 ID 唯一；较旧的无 ID 文件使用明确的 `index:N` 身份。
缺失执行次数、保存错误及不支持的输出类型仍为未核验。输出和执行次数不能证明
代码实际执行过、执行顺序正确或输入完整。MIME 内容仅计算哈希，不执行、不渲染。

## 声明并审核生成关系

```sh
paperdelta --lang zh-CN provenance preview training --kind notebook --source analysis.ipynb --cell metrics --input observations.csv --input run_notebook.py --output results/metrics.csv --rationale "已复核所选单元格和列明依赖" --out training-plan.json
paperdelta --lang zh-CN provenance accept training-plan.json
paperdelta --lang zh-CN check --report build/review
```

先复核提案，再明确执行 `accept`。多个单元格、输入或输出分别重复 `--cell`、
`--input`、`--output`。Notebook 至少选择一个代码单元格；Quarto 不使用 `--cell`。
导出稿使用 `--kind quarto --source paper.qmd --output paper.pdf`，用 `--input`
明确列出数据、图片、模板等依赖。

确认会备份配置并保存带内容身份的记录。同名更新需要重新预览并指定 `--replace`。
源文件、所选代码、保存输出、执行次数或列明文件变化后，新鲜度失效；缺失或不可读
依赖保持未知。Notebook 元数据变化也会改变整份文件身份，须复核后再更新记录。

`declared` 只表示作者声明这些文件之间的关系。记录通过仅表示字节未变，不能证明
计算执行、依赖完整、图形内容正确或科学结论成立。

## 可选：观察明确指定命令的执行

普通 `check`、Studio、MCP 和可复用 Action 不执行项目代码。
独立的 CLI 命令 `provenance run` 只运行使用者明确指定的命令：

```sh
paperdelta --lang zh-CN provenance run training --kind notebook --source analysis.ipynb --cell metrics --input observations.csv --input run_notebook.py --output results/metrics.csv --rationale "运行已复核的 Notebook 导出程序" --out run-plan.json --command python run_notebook.py
paperdelta --lang zh-CN provenance accept run-plan.json
```

`--command` 放在最后，后续参数都属于外部命令。使用所选环境的可执行程序，并先检查
导出脚本。Quarto 示例：

```sh
paperdelta --lang zh-CN provenance run render --kind quarto --source paper.qmd --input results/metrics.csv --output paper.pdf --rationale "渲染已复核的当前源稿" --out render-plan.json --command quarto render paper.qmd --to typst --no-execute
```

Notebook／Quarto 是可选外部程序，不是 PaperDelta 必需依赖。命令在项目目录执行，
不隐式经过 shell。记录退出码 0、起止时间、本地标准输出／错误日志哈希和列明输入的
前后身份。Notebook 代码前后必须相同，保存输出可以改变。非零退出、超时、代码或
列明输入变化不会生成成功提案。默认超时 600 秒，`--timeout` 接受 1–3600 秒。
日志留在 `.paperdelta/run-logs/`。

`observed_command` 区分实际进程观察与单纯声明，之后仍需单独确认。前后相同不代表
持续监控，无操作命令也可能成功退出。本地记录可编辑；环境状态、隐藏输入、命令参数
和日志仍需作者复核，不能证明因果来源或可复现性。分享[便携审查包](review-bundle.md)
时明确选择记录；日志不会自动加入。

## 生成确定性的结果片段

选择已确认数值绑定 ID，复用它们的指标、单位、统计约定、舍入和显示规则：

```sh
paperdelta --lang zh-CN fragment preview result_table --occurrence table_accuracy --occurrence table_baseline --format markdown --layout table --path generated/results.md --out fragment-plan.json
paperdelta --lang zh-CN fragment accept fragment-plan.json
```

LaTeX 使用 `--format latex` 和 `.tex` 路径。`--layout value` 要求恰好一个绑定，
用于单个数值。表头跟随命令语言；中文 LaTeX 片段需要支持 Unicode 的论文配置。
相同输入、选择顺序、语言和显示规则产生相同文本；时间和哈希存在单独记录中。

预览不写目标文件。明确确认仅写入审核过的生成文件与记录，不编造正文，不改写科学
结论。把片段加入论文或调整位置仍由作者明确操作。即使舍入数值相同，输入、指标／
显示定义或生成内容变化也会被检查。更新时使用 `--replace`；已有无关文件或被手改的
片段会被拒绝覆盖，须另选路径保留手工编辑。更新会备份旧生成文件及配置；写入为
单文件操作，不是跨文件系统事务。

## 查看修订清单

```sh
paperdelta --lang zh-CN revisions --baseline submitted-v1
```

JSON 清单及离线 HTML／文本报告列出受影响正文、表格、结论、图形、生成记录与片段。
`review_refreshed` 表示绑定数值已符合变更后的证据，仍需复核上下文。未知证据单独
列出；错误的比较结论不能仅靠替换数字修复。图形和导出任务要求重新生成并审核结果。
相等的数值从不自动建立证据关系。

Studio 的“Notebook、导出稿与结果片段”面板支持单元格查看、声明预览、明确确认、
片段生成和修订清单。切换语言保留表单与选择，使旧确认预览失效。
Studio 没有命令执行接口。

## 兼容性与验证范围

确认的生成／片段引用要求配置 schema **10**。仍可读取配置 1–9；空的新字段省略，
以保留旧身份。新报告使用 schema **9**，增加可选的 `provenance`、`fragments`
状态和数值用途 `usage`（`prose`／`table`）。旧快照仍可读取。论文覆盖计数继续只计算
数值位置、结论与图形；生成记录和片段单独计数，但其失败／未知会影响整体退出码。
PR 摘要明确显示被删除记录，便携复查保留这些声明和所需输入。

兼容的 1.5 草稿可在输入未变时按正常审核流程恢复。通过 `schema producer-record`、
`producer-proposal`、`fragment-record`、`fragment-proposal` 查看新记录约定。
哈希是内容身份，不是签名。

1.9.38／Typst PDF 渲染，验证上游数据变化、表格和片段已更新但正文、比较结论、图形和

[Quarto](https://quarto.org/docs/get-started/)，然后运行：

```sh
python tools/validate_notebook_workflow.py --out build/notebook-workflow --quarto quarto
```
