# PaperDelta 1.5：与合作者审查实验变化

[English](../v1.5.md)

1.5 增加可复用 GitHub Action、明确的问题状态变化、SARIF 诊断与可选择内容的便携审查包。
稿件格式、证据身份及明确接受绑定的规则继续兼容已有声明。

## 在论文仓库接入 Action

将 [paper-review.yml](../../examples/ci/paper-review.yml) 复制到论文仓库的
`.github/workflows/`。把仓库变量 `PAPERDELTA_REVISION` 设置为经过复核的
[PaperDelta 1.5 或更新发行版](https://github.com/amos689/paperdelta/releases)的完整提交 SHA。
工作流分别检出可信 Action 和待审查论文，使用只读仓库权限，并在失败时保留报告。

提交原始稿件状态前运行：

```sh
paperdelta --lang zh-CN snapshot create submitted-v1
```

将配置、已声明输入及 `.paperdelta/baselines/submitted-v1.json` 一并提交。
如使用其他快照名，请修改工作流。CI 从 PR 目标提交读取已保存快照；PR 中替换同名文件
不会改变比较基准。这是与已保存检查点比较，不代表重新执行了目标提交的实验。
缺少快照时明确显示无法进行历史比较。

Action 输入包括 `project`、必填 `base-commit`（已获取的完整 SHA）、`snapshot`、
`config`、`report` 和 `lang`（`en` 或 `zh-CN`）。其余默认值依次为 `.`、
`submitted-v1`、`paperdelta.yaml`、`build/paperdelta`、`en`。
输出为 `exit-code` 和相对于工作区的 `report-path`。Action 在隔离环境安装选定的可信源码，
不执行论文代码，并禁止把 Git 管理文件作为检查输入或输出位置。
安装依赖需要软件包索引；稿件检查在本地完成。

通过工作流的产物链接下载报告。退出码 0 表示已接受的检查通过，1 表示存在失败，
2 表示检查不完整或输入无效。即使当前检查通过，配置变更和覆盖减少仍需要复核。
CI 不发布 PR 评论。

## 理解变化摘要

| 分类 | 含义 |
| --- | --- |
| 新报告的失败 | 当前失败在已保存快照中没有被记录为失败。 |
| 已解决的失败 | 原失败现在通过，且声明契约未变、基准契约可验证。 |
| 未验证 | 无法验证当前证据或必要位置；不能据此宣称原问题已解决。 |
| 删除的绑定 | 原来检查的声明消失，检查覆盖减少。 |
| 持续失败 | 同一声明继续失败。 |
| 契约变化 | 声明或依赖变了；当前通过不能证明原问题已修复。 |
| 无比较基准的当前失败 | 没有可用快照，不编造历史变化。 |

契约变化和失败分类可以重叠。摘要每类最多显示 50 项，`ci-context.json` 保存完整列表。
即使仅修改实验数据，也会检查全部已配置稿件位置。只有快照中的配置哈希与目标配置
一致时，才允许报告已解决。

## SARIF 与稿件原位置

常规报告目录在 HTML、JSON、Markdown 之外增加 `report.sarif`。文本格式使用实际源码行号
和 Unicode 列号。Word/PDF 保留原生位置和报告锚点，不伪造文本行号。下载并解压报告后，
打开 `report.html` 查看页面高亮、表格及段落位置。本地 HTML 锚点不是 GitHub 托管的批注；
不同 SARIF 查看器对二进制稿件位置的呈现可能不同。

未知检查映射为 SARIF 警告，同时保留原始 `paperdeltaSeverity`。示例工作流将 SARIF
作为产物保存。启用 GitHub 代码扫描是可选仓库设置，需要相应权限和支持条件，详见
[GitHub SARIF 文档](https://docs.github.com/en/code-security/reference/code-scanning/sarif-files/sarif-support)。

## 与 paper-preflight 一起使用

同一工作流包含独立的参考文献完整性作业，固定到
[paper-preflight 0.4.0](https://github.com/amos689/paper-preflight/tree/d44231c87e27221e057eeb0ca44d3977574b351e)。
它检查引用和参考文献；PaperDelta 检查实验声明与稿件内容的对应关系。
任何一方通过都不能替代另一方的结果。不需要时可删除参考文献作业。

这个可选作业默认查询学术数据源。将其 `offline` 设置为 `true` 可只读缓存，缺少缓存仍
表示检查不完整。其语言参数为 `en`/`zh`，PaperDelta 则为 `en`/`zh-CN`。
两者保留独立报告与退出状态，PaperDelta 不增加 paper-preflight 依赖。

## 分享离线审查

Studio 支持先预览选定报告与明确选中的已检查输入，再导出审查包。
CLI 可以检查包内容，并在新目录重放完整审查包。详见[便携审查指南](review-bundle.md)。
切换语言保留文件选择，并要求重新复核刷新后的预览才能下载。

## 验证与兼容

配置 schema 9、报告 schema 8 继续兼容。增加变化列表的 `ci-context.json` 使用 schema 2，
新审查包清单使用 schema 1。兼容的 1.4 Studio 草稿可按正常复核流程恢复。

本地证据覆盖五种格式、两种语言的十条自有浏览器流程，全新 Git 仓库的实际隔离 Action
入口运行，保留范围的离线重放，缺失输入、过期预览、压缩包路径和完整性，以及独立的
离线 paper-preflight 运行。这些是开发者操作的检查，不是独立易用性研究，也不验证学术
数据源的准确率。[交付记录](roadmap.md)仅在完成发布后登记十七项 CI 和精确公开包验证。
