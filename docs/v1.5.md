# PaperDelta 1.5: review experiment changes with collaborators

[简体中文](zh-CN/v1.5.md)

Version 1.5 adds a reusable GitHub Action, explicit finding transitions, SARIF
diagnostics and selected portable review files. Manuscript formats, evidence
identity and explicit binding acceptance keep their existing contracts.

## Use the Action in a paper repository

Copy [paper-review.yml](../examples/ci/paper-review.yml) into the paper repository's
`.github/workflows/` directory. Set its repository variable `PAPERDELTA_REVISION`
to the reviewed full commit SHA of a 1.5-or-newer
[PaperDelta release](https://github.com/amos689/paperdelta/releases).
The workflow checks out that trusted Action separately from the proposed paper,
uses read-only repository permissions and keeps reports on failure.

Before committing the original submission state, run:

```sh
paperdelta snapshot create submitted-v1
```

Commit its configuration, declared inputs and `.paperdelta/baselines/submitted-v1.json`.
Change the workflow's snapshot name if needed. CI reads this saved snapshot from
the PR target commit; replacing a same-named snapshot in the PR does not change
the comparison. This is comparison to a saved checkpoint, not a fresh execution
of the target commit's experiment. An absent snapshot remains visible as unavailable.

The Action inputs are `project`, required `base-commit` (full fetched SHA),
`snapshot`, `config`, `report` and `lang` (`en` or `zh-CN`). Defaults are `.`,
`submitted-v1`, `paperdelta.yaml`, `build/paperdelta` and `en`, respectively.
Outputs are `exit-code` and the workspace-relative `report-path`. The Action
installs its selected trusted source in an isolated environment, executes no paper
code, and refuses Git administration files as inputs or output destinations.
Dependency installation needs a package index; manuscript checking is local.

The workflow downloads reports through its artifact link. Exit 0 means accepted
checks passed, 1 means at least one failed, and 2 means checks were incomplete or
inputs invalid. Configuration edits and coverage reductions still require review
even when current accepted checks pass. CI does not post PR comments.

## Understand the change summary

| Category | Meaning |
| --- | --- |
| Newly reported failures | A current failure was not recorded as failed in the saved snapshot. |
| Resolved failures | A previous failure now passes under an unchanged, verified declaration contract. |
| Unverified | Current evidence or a required position cannot be verified; this never resolves a failure. |
| Removed bindings | A previously checked declaration has disappeared; coverage decreased. |
| Continuing failures | The same declaration remains failed. |
| Changed contracts | Declarations or their dependencies changed; a pass does not establish that the old failure was fixed. |
| Current failures without comparison | No saved comparison is available; no historical change is invented. |

Contract and failure categories can overlap. The summary shows at most 50 entries
per category; `ci-context.json` retains the complete lists. All configured paper
positions are checked when only experiment data changes. The baseline's configuration
hash must match the target configuration before a resolution can be claimed.

## SARIF and original manuscript positions

Every normal report directory now includes `report.sarif` alongside HTML, JSON and
Markdown. Text formats use their actual source line and Unicode column. Word/PDF
findings retain native positions and report anchors without fabricated text line
numbers. Download and extract the report artifact, then open `report.html` for
page highlights and table/paragraph locations. A local HTML anchor is not a hosted
GitHub annotation. SARIF consumers may present binary locations differently.

Unknown checks are SARIF warnings with their original `paperdeltaSeverity` retained.
The supplied workflow keeps SARIF as an artifact. Enabling GitHub code scanning is
an optional repository decision requiring its own permissions and supported setup;
see [GitHub's SARIF support](https://docs.github.com/en/code-security/reference/code-scanning/sarif-files/sarif-support).

## Work alongside paper-preflight

The same workflow has an independent reference-integrity job pinned to
[paper-preflight 0.4.0](https://github.com/amos689/paper-preflight/tree/d44231c87e27221e057eeb0ca44d3977574b351e).
It checks citations and references; PaperDelta checks declared experimental evidence
against manuscript statements. Neither tool's successful result substitutes for
the other's. Remove the reference job if it is not needed.

That optional job performs registry lookups by default. Set its `offline` input to
`true` for cache-only checking; a cache miss remains incomplete. Its language values
are `en`/`zh`, whereas PaperDelta uses `en`/`zh-CN`. Reports and exit codes stay separate.
No dependency on paper-preflight is added to PaperDelta.

## Share an offline review

Studio can preview selected reports and explicitly selected checked inputs before
exporting an archive. The CLI inspects and replays complete archives in a new folder.
See the [portable review guide](review-bundle.md). Language switches preserve file
choices and require reviewing the refreshed preview before downloading.

## Verification and compatibility

Configuration schema 9 and report schema 8 remain compatible. `ci-context.json`
uses schema 2 for the added transition lists; the new bundle manifest uses schema 1.
Saved compatible 1.4 Studio drafts can be restored through normal review.

Local evidence covers ten authored browser flows across five formats and both
languages, actual isolated Action entry-point runs on fresh Git repositories,
scope-preserving offline replay, missing inputs, changed previews, archive path
and integrity checks, and an independent offline paper-preflight run. These are
developer-operated checks, not independent usability studies or validation of
scholarly registry accuracy. The [delivery ledger](roadmap.md) records the 17-job
CI and exact public package verification only after publication completes.
